## Highlights

XFiles 1.4.0-smb is a large feature release built on top of `v1.3.9-smb`. It turns the fork into a much stronger NAS/media file manager while adding dedicated mobile and Google TV experiences.

- **Rust-first SMB2/3 I/O**: the native Rust SMB engine is now the preferred backend, with SMBJ retained as a compatibility fallback when the native layer is unavailable or incompatible.
- **Visual video storyboards**: inspect a video before opening it, generate up to 120 timeline frames, jump directly to a frame, and reuse the same timeline in normal playback and Chromecast controls.
- **Chromecast on mobile**: cast local, SMB and provider-backed media, control playback from the app or notification, and return to an active Cast session from a persistent mini-player.
- **Dedicated Google TV edition**: a separate TV package with a single-pane, D-pad-first browser and remote-first video controls.
- **Built-in update checks**: mobile and TV can detect edition-matching signed builds from GitHub Releases, validate them, and hand updates to Android's package installer.
- **Stronger app-to-app file workflows**: Android share-target support, an external local/SMB file picker, and a transactional seekable SMB output bridge for media-processing apps.

## SMB / NAS

- Added a backend abstraction for SMB random access and promoted the **Rust SMB2/3 engine** to the preferred `auto` backend.
- Kept **SMBJ fallback** and explicit Rust/SMBJ build switches so the native engine can fail safely rather than breaking access.
- Packaged and symbol-validated the Rust JNI libraries for **arm64-v8a, armeabi-v7a and x86_64** in normal debug, retrievable debug and release builds.
- Added native prefetch support and iterated the media path through rolling cache reclamation, deferred refill, foreground pipeline limits, adaptive read-ahead and recent-throughput EWMA tuning.
- Restored Rust playback as the default after stabilizing Media3 access with aligned/coalesced reads and a short speculative-prefetch idle grace.
- Prioritized foreground playback reads over background thumbnail/storyboard work so visual indexing does not starve active video playback.
- Reworked proxy I/O with multiple handler lanes, sequential read-ahead, bounded write batching and negotiated SMB buffer sizes.
- Fixed proxy short reads at read-ahead boundaries, including large offsets beyond 4 GiB.
- Added seekable SMB output truncation (`setLength`) for restartable exports.
- Hardened remote-output commit semantics: flush pending writes, wait for descriptor release, verify expected length and tail readability, and never rename an incomplete partial file into the visible final name.
- Added best-effort cleanup for stale transactional `.clipforge-partial-*` files.

## Video storyboards and playback

- Added an **on-demand storyboard** opened from a video thumbnail without changing normal row-tap playback.
- Storyboard frames are generated progressively and cached; currently visible frames are prioritized so the first useful preview appears sooner.
- Added configurable sample count from **6 to 120 frames** in 2-frame steps.
- Added configurable minimum frame spacing from **1 to 10 seconds**, with automatic clamping for short videos.
- Tapping a storyboard frame opens or seeks the video at that timestamp, with explicit storyboard starts taking priority over saved resume positions.
- Added a finer long-press timeline preview and current-playback highlighting.
- Reused the storyboard inside the normal video player and Cast controller.
- Improved long-video sampling so previews cover the whole runtime instead of clustering near the beginning.
- Prioritized thumbnails near the visible viewport in both the browser and player.
- Fixed blank/white storyboard frames by detecting unreliable sync-frame decodes and retrying the exact/closest frame path.
- Fixed persisted resume restoration so the saved position is supplied before player preparation begins.
- Kept the local storyboard in real reserved layout space between the video surface and playback controls so it no longer covers the seek UI or video.
- Added **±5 second Picture-in-Picture actions**, kept PiP controls hidden during seek buffering, stabilized storyboard position around PiP transitions, and stopped playback correctly when PiP is dismissed.
- Polished top-player actions so Cast and settings controls align and appear with the player chrome instead of remaining permanently over the video.

## Chromecast on the mobile edition

- Added Chromecast playback for mobile XFiles using a temporary HTTP Range relay for local, SMB and provider-backed media.
- Added a full Cast control surface with playlist navigation, play/pause, seeking and current-position feedback.
- Added a Cast storyboard: portrait uses a compact vertical timeline, landscape uses a horizontal strip, and the current playback frame can be brought back into view without seeking.
- Highlight the actively cast item in the browser.
- Added a persistent **Cast mini-player** when returning to the file browser.
- Added ongoing notification controls for previous/next, ±10 seconds and play/pause; tapping the notification returns to Cast controls.
- Coalesced repeated seek and next/previous commands instead of flooding the receiver with intermediate requests.
- Added cumulative seek feedback such as `+20s` / `+30s`, optimistic UI updates and smoother progress tracking.
- Reuse and prewarm SMB handles for Cast Range requests, prewarm adjacent playlist entries and retire stale open-ended relay streams after newer seeks.
- Enabled low-latency relay socket behavior and preserved reconnect-once handling for transient SMB transport failures.
- Fixed Cast handoff state so a previously playing video's identity no longer flashes in the controller while a newly selected item is being handed to the receiver.
- Added tests for new-session handoff, reused sessions, consecutive selections, delayed callbacks, failures and disconnects.

> Chromecast is a **mobile-edition feature**. The TV edition intentionally stays focused on direct TV playback and does not include the Cast stack.

## Google TV edition

- Split XFiles into separate **mobile** and **Google TV** product flavors/packages so TV behavior does not distort the touch UI.
- Added Leanback launcher/banner support and TV-specific resources.
- Made the TV browser truly **single-pane** to reduce unnecessary rendering/I/O and remove D-pad focus ambiguity.
- Added focus-revealed left/right action rails, including direct Settings access.
- Hardened startup focus, row-to-row Up/Down navigation, rail navigation and browser-return focus across multiple device-testing iterations.
- Changed Back behavior so transient UI closes first, then folder navigation moves upward, and exiting happens only from the top level.
- Added remote-first video controls: center toggles play/pause, left/right seek 10 seconds, up shows controls, down hides them, and Back hides controls before exiting playback.
- Removed touch-only orientation/close controls from the TV player.

## File operations, sharing and external integration

- Added **one-level folder flattening**: move the contents of immediate child folders up one level and remove only folders that are left empty. The operation works on local storage and SMB connection roots and reuses existing conflict handling.
- Added XFiles as an Android `ACTION_SEND` / `ACTION_SEND_MULTIPLE` share target and route received files into the existing destination-selection flow.
- Preserve useful MIME types for multi-file shares, including `video/*` when sharing multiple video formats.
- Added `app.local1st.files.action.PICK_FILES` for external callers to select local or SMB files while XFiles keeps SMB credentials private and returns temporary read-granted URIs.
- Added a transactional `PICK_OUTPUT` SMB bridge for media tools: seekable random-access writes go to a hidden partial file and are promoted only after an explicit successful commit.
- Fixed move/copy entry points when the opposite pane is browsing an APK/archive while still preventing writes into read-only archive paths.
- Refreshed folder/file counts after operations and kept browser operation messages clear of the floating bottom toolbar.

## Updates and distribution

- Added a built-in updater to both editions with edition-specific APK selection and package/build validation.
- Added Settings controls for automatic checks, manual **Check now**, current version/build, last successful check and inline status.
- Improved PackageInstaller handoff so required Android install confirmation appears immediately and XFiles can relaunch after a successful self-update.
- Release CI now produces signed **mobile APK**, **TV APK**, and a **mobile AAB**.

## Quality, tests and CI

- Added API 35 x86_64 Android Emulator smoke tests that install/launch the mobile app and exercise a background/foreground lifecycle round trip.
- Kept mobile and TV unit-test variants in CI and expanded regression coverage for Cast handoff, SMB proxy buffering, MIME selection and video resume behavior.
- Centralized Rust Android JNI builds and validates required symbols before APK assembly.
- Continued stable signing for test builds so installed development builds can be upgraded instead of appearing as unrelated apps.

## Upgrade notes

- Minimum supported Android version remains **Android 8.0 / API 26**.
- The normal mobile package remains the main XFiles app; the TV edition is a separate installable package.
- Existing SMB settings remain usable. `auto` now prefers the bundled Rust backend and falls back to SMBJ only when needed.
