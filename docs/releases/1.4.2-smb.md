## XFiles 1.4.2-smb — update consolidation and media improvements

The first stable version after `v1.4.1-smb`. Includes the retirement of Nightly update channels, Mobile and TV file/player fixes, image casting on Mobile, and the current Rust SMB implementation.

### Updates and distribution

- Removed the **Normal / Nightly** update channel selector, stored-channel lookup and Nightly release handling in Mobile and TV. Manual and startup update checks now use the single signed `debug-latest` feed.
- Stopped the rolling `nightly` prerelease workflow. The legacy GitHub Nightly release and tag are retired by the release job.
- Kept the Mobile diagnostic side-by-side APK and the existing auto-update switch, edition checks and installation validation.
- A matching-version debuggable Normal APK can replace a non-debuggable normal-package build at the **same build number** for migration; downgrades and same-build reinstallation of Debug are still rejected.
- Published this version as a **stable release**, with separate signed Mobile and Google TV APKs. CI also produces a Mobile AAB artifact.

### Media and file browsing

- Added **image casting from the Mobile image viewer** for supported local, provider-backed and SMB images through the existing temporary HTTP relay, with swipe-to-next image handling.
- Improved landscape video player layout and storyboard alignment, including a single vertical storyboard column and removal of stray white borders.
- Added storyboard follow-along navigation when playback moves between frame ranges.
- Fixed tree folder/file counters not updating and improved SMB file deletion for read-only items.
- Kept the pinned Rust SMB JNI backend and CI validation.

### Compatibility and migration notes

- The **Root / Shizuku privileged file transport** and former App Manager functionality have been removed from XFiles; these features are not part of this release.
- Existing installs with `selected_track=nightly` will ignore the legacy preference once updated. **Older Nightly-selected app builds cannot discover the new Normal endpoint by themselves.** Install the current signed Normal Mobile/TV APK **once** over the old app (do not uninstall if you want to keep application data). Subsequent checks use `debug-latest`.
- Stable-release APKs and `debug-latest` APKs share the normal package identities, but the auto-updater follows the Debug feed. Device-side package signing and update compatibility should be checked on the target device before wide rollout.
- Android 8.0 / API 26 or later is required. Mobile Cast still needs a compatible Google Cast receiver and LAN reachability.
- CI tests do **not** certify physical Chromecast output, or actual Android package replacement from older Nightly/stable installs. Those remain device acceptance checks.
