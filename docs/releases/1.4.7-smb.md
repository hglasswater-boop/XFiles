## XFiles 1.4.7-smb — SMB選択時の宅内IPレンジ判定・WireGuard自動OFF改善

### 改善内容

- SMBサーバーを選んでフォルダ一覧に接続する際、スマホが接続している**物理Wi-FiのIPアドレスとプレフィックス（サブネットマスク）**を取得します。
- NASのIPがWi-Fiと**同一IPレンジ**である場合、VPNを通さないWi-Fi専用TCPソケットでNASのSMBポートに接続確認します。到達できた場合のみ、設定したWireGuardトンネルにDOWN要求を出します。
- 同一レンジだけではVPNを切断しません。NAS不達・Wi-Fiなし・VPNロックダウン・名前解決失敗では停止しません。TCP到達確認のタイムアウトは最大600ms/対象アドレスです。
- WireGuardの公式Receiver（`com.wireguard.android.model.TunnelManager$IntentReceiver`）を明示してUP/DOWNを送るよう変更。送信の診断ログはAndroidログの `XFilesWireGuard` タグに残します。
- IP判定は固定の/24ではなく端末の実際のプレフィックスを使います（/23, /16, IPv6等にも対応）。IPv4とIPv6を誤って同一サブネットとは判断しません。

### 使用方法

1. XFilesのSMB接続設定でWireGuard連携をONにし、正しいトンネル名を設定します。
2. 公式WireGuardアプリの **Allow remote control apps** をONにし、XFilesに操作権限を許可します。
3. 自宅Wi-Fiにつないだ状態でXFilesからNASのSMBサーバーを開きます。
4. NASのTCPポートにWi-Fiから到達すれば自動OFFを要求します。SMB接続行の選択時に毎回判定されます（頻繁なDOWNは抑制）。

### 制約・セキュリティ

- **現バージョンの自動OFFは同一サブネット接続が条件**。別VLAN・別サブネットのNASには自動OFFしません。
- 他所のWi-Fiが自宅と同じIPレンジで、同じIPとTCPポートに別のサービスを公開している場合、IPとTCPだけでは本物のNASとは保証できません。
- WireGuardが「常時接続/ VPN以外をブロック」等の設定の場合、Wi-Fi直接ソケットを使えずVPN停止を要求できない場合があります。
- 外部アプリのブロードキャストには状態ACKがなく、送信成功はVPN切断の成功証明ではありません。端末でWireGuardアプリが実際にOFFになるか実機で確認してください。
- Wi-Fi変更時に常時監視して切断する方式ではありません。XFilesのSMB接続開始時の判定です。
